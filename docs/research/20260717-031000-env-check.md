## 3. Emscripten 安装策略（不污染全局环境）

用户指定优先级：uv → conda → podman/docker。分析：

- **uv**：Python 包管理器。Emscripten 不是 pip 包，uv 无法直接安装 emcc。
- **conda**：本机未安装。
- **podman/docker**：可用，`emscripten/emsdk` 官方镜像是一种方案，但容器内文件映射、36 核并行编译与缓存管理会增加复杂度。
- **选定方案**：将 `emsdk` 官方安装器**克隆到工作目录内**（`tools/emsdk/`），`./emsdk install latest` 全部内容均落在该目录下，激活仅改写目录内文件。这完全符合"本地环境、不污染全局"的要求，且比容器方案更便于 CMake 集成与增量编译。Python 依赖由系统 python3 提供（emsdk 脚本自身需要，不安装任何全局包）。

## 4. 风险与注意事项

- Ymir 的 `vendor/` 依赖以 git submodule 提供，浅克隆未含 submodule，需 `git submodule update --init --recursive`。
- Ymir 的 `cmake/DetectArchitecture.cmake` 不认识 wasm32，配置期会 `FATAL_ERROR`，需打补丁（详见 research 报告与 plan）。
- 本机无需安装任何 SDL3 系统依赖：Web 版不编译 `apps/ymir-sdl3`，只编译 `libs/ymir-core` + 自写桥接层。
